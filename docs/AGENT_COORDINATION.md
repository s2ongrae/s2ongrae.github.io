# 에이전트 동시 작업 규칙 (피클 · 집 노트북 · 회사 PC · 제미니)

> 이 문서는 공개 저장소에 있다. 키·주소·개인정보·고객 정보를 넣지 않는다.
> 목적: 같은 레포를 여러 에이전트(세션)가 건드려도 **서로 덮어쓰거나 브랜치가 갈라지지 않게** 한다.

## 0. 누가 누구인가

| 주체 | 하는 일 | 레포를 고치는 방식 |
|---|---|---|
| 피클(레이) | 총괄 비서, 웹 자동화, 긴급·직접 수정 | 직접 커밋·푸시, `status/agent.json` 갱신 |
| 집 노트북 `hub-agent` | 무인 워커. 오더(`Command_Queue`)를 받아 실행 | `auto(Q-…)` 커밋을 `main` 에 직접 푸시(보통 **새 파일 위주**) |
| 회사 PC (Claude CLI) | 사용자가 직접 시키는 개발·정리 | 이 문서의 규칙대로 |
| 제미니 | 기획·설계 참모 | 코드 수정 안 함(문서 제안만) |

기기 사이의 **진실의 원천은 GitHub `main`** 이다. 구글 드라이브는 공유 통로가 아니다(자료 보관용).

## 1. 기본 원칙 — 세 겹의 안전장치

### 1겹. git 규칙 (모든 기기·모든 에이전트)
1. 작업 시작 전 **`git pull --ff-only`**. 실패(ff 불가)하면 **멈추고 사람에게 보고**한다. 임의로 merge·`--force`·`reset --hard` 하지 않는다.
2. 한 가지 일 = 한 커밋. 테스트 통과 후 **바로 `git push`** 한다(들고 있지 않는다).
3. `main` 강제 푸시·커밋 재작성 금지.
4. 푸시가 거절되면(그사이 누가 푸시) `git pull --rebase` 로 한 번만 시도하고, 충돌이 나면 `rebase --abort` 후 보고한다.
5. 다른 에이전트가 만든 `auto/…`·`agent/…` 브랜치와 `status/agent.json` 은 **직접 고치지 않는다**.

### 2겹. 한 기기 안: 레포 하나 = 세션 하나 (agent-lock)
- 세션을 시작할 때 `agent-lock lock <레포> "작업명"`. 이미 쓰는 세션이 있으면 **종료코드 2 + 안내**가 나오고, 그러면 아래 3겹(워크트리)을 쓴다.
- 끝나면 `agent-lock unlock <레포>`. 세션이 죽어도 PID 가 없으면 낡은 잠금으로 보고 풀린다(6시간 지나도 풀림).
- 잠금 표시는 `.git/agent.lock`(git 에 안 올라감). **같은 기기** 세션끼리만 막는다.
- 현황: `agent-lock status` (레포별 브랜치·변경 수·잠금).

### 3겹. 같은 레포를 병렬로 해야 할 때: 워크트리
- `agent-lock wt <레포> <작업이름>` → 로컬 디스크(`%USERPROFILE%\agent-wt`)에 작업 복사본 + 브랜치 `agent/<기기>/<작업이름>` 생성(만들기 전에 `pull --ff-only`).
- 세션은 그 폴더에서 연다. 파일이 서로 안 겹치므로 동시에 돌려도 된다. **드라이브 폴더 안에는 만들지 않는다**(동기화·`npm install` 사고 방지).
- 끝나면 테스트 → `agent-lock wtdone <레포> <작업이름>`: `origin/main` 위로 rebase → `main` 에 ff 병합 → 푸시 → 워크트리·브랜치 정리. 충돌이면 중단하고 보고(자동 해결 없음).

## 2. 기기 사이 (피클 ↔ 노트북 ↔ 회사 PC)

- **상태 알림**: 작업을 시작하면 `pcbeat start "작업명" <프로젝트>`, 끝나면 `pcbeat done`(커밋은 `post-commit` 훅이 자동 알림). 포털 `🖥️ 작업 관제` 카드에서 다른 기기가 **같은 프로젝트를 작업 중인지** 먼저 본다.
- 다른 기기가 같은 프로젝트를 작업 중이면: ① 파일이 안 겹치는 일이면 진행, ② 겹칠 수 있으면 **기다리거나 사람에게 물어본다**(워크트리는 기기 사이 충돌을 못 막는다).
- 노트북 `hub-agent` 는 `main` 에 직접 푸시한다. 그래서 사람·회사 PC 는 **작업 전 pull, 작업 후 즉시 push** 를 더 엄격히 지킨다. `hub-agent` 의 `auto(Q-…)` 오더 범위(어느 파일을 만지는지)는 오더 프롬프트에 적혀 있으니, 같은 파일을 동시에 고칠 일은 오더 큐에 먼저 넣거나 순서를 맞춘다.
- 오더 큐(`Command_Queue`)가 **기기 간 일감 배분의 유일한 통로**다. 같은 일을 두 곳에서 따로 시작하지 않는다.

## 3. 파일 소유권 (단일 작성자)

| 파일·자원 | 쓰는 쪽 | 나머지는 |
|---|---|---|
| `status/agent.json` | 피클만 | 읽기만 |
| `Command_Queue` 시트·`Audit_Log` | 포털 서버(GAS)·`hub-agent` 워커 | 포털 오더함으로만 접수 |
| `.git/hooks/post-commit` (pcbeat) | 각 기기가 자기 것 | 덮어쓰지 않는다 |
| 각 기기의 `.freellmapi.key`·`.portal-beat.json` | 그 기기 | 커밋·복사 금지 |
| 레포 `CLAUDE.md`·`AGENTS.md` | 누구나(작게, 한 가지씩) | 규칙을 바꾸면 사람에게 알린다 |

## 4. 충돌이 났을 때 (순서)
1. 멈춘다. 하던 변경은 지우지 않고 브랜치(`agent/<기기>/<작업>`)로 보관한다.
2. 상황을 한 줄로 보고한다: 어느 레포 · 어느 파일 · 누가 먼저 푸시했나.
3. 사람이 정하기 전에는 `reset --hard`·`push --force`·충돌 파일 통째 덮어쓰기를 하지 않는다.

## 5. 도구 설치 (기기마다 한 번)

```powershell
irm https://s2ongrae.github.io/tools/agent-lock.ps1 -OutFile "$env:LOCALAPPDATA\agent-lock.ps1"
function agent-lock { powershell -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\agent-lock.ps1" @args }
```
- 위 `function` 줄을 `$PROFILE` 에 넣으면 항상 쓸 수 있다.
- `AGENT_ROOT`(레포들이 모인 상위 폴더)를 환경변수로 두면 `agent-lock status`·`lock <이름>` 이 어디서든 동작한다.

## 6. 한계 (정직하게)
- `agent-lock` 은 **같은 기기의 협조적 잠금**이다. 강제력은 없고, 세션이 확인하지 않으면 못 막는다 → 각 레포 `CLAUDE.md` 의 "작업 시작 절차"로 습관화한다.
- 기기 사이는 잠금이 아니라 **GitHub(ff-only)·`pcbeat` 상태·오더 큐**로 맞춘다. 실시간 상호 배제는 없다.
- 노트북 `hub-agent` 의 자동 푸시는 막지 않는다. 대신 위 2번 규칙으로 빈도를 낮춘다.
